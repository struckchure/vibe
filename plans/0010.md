# 0010 — App-wide connection keeper

| Field | Value |
|-------|-------|
| **Status** | done |

## Summary

Move auto-connect from chat-scoped (`ChatThread`) to app-scoped so **all contacts** stay announced on WebTorrent trackers and libp2p overlay while the app runs. Add `vibe://chat/{conversationId}` deep links and mobile background hooks.

## Changes

- [`connection-keeper.ts`](../src/lib/connection-keeper.ts) — singleton keeper: tracker + signaling + transport per contact
- [`use-connection-keeper.ts`](../src/hooks/use-connection-keeper.ts) — React bridge in `AppProviders`
- [`use-auto-connect.ts`](../src/hooks/use-auto-connect.ts) — read-only UI selector over keeper state
- [`use-chat-deep-link.ts`](../src/hooks/use-chat-deep-link.ts) — `vibe://chat/{conversationId}` navigation
- [`use-app-lifecycle.ts`](../src/hooks/use-app-lifecycle.ts) — `refreshAllConnections` on resume/focus
- Android [`KeepAliveService.kt`](../src-tauri/gen/android/app/src/main/java/com/vibe/open/KeepAliveService.kt) — foreground notification while app session is open
- iOS [`Info.ios.plist`](../src-tauri/Info.ios.plist) — `fetch` + `processing` background modes

## Mobile background limits

| Layer | Background behavior |
|-------|---------------------|
| libp2p (Rust) | Keeps running while OS allows the process |
| WebTorrent tracker (JS) | Suspended when WebView sleeps (especially iOS) |
| WebRTC data channels (JS) | Suspend with WebView |

On resume, `refreshAllConnections()` re-announces on all tracker rooms. libp2p rendezvous/gossipsub covers signaling when JS is frozen.

## Manual test

1. Open app on device A (chat list only) — device B opens chat → connects without A viewing the thread.
2. Navigate away from a chat on A — tracker sessions stay up.
3. Open `vibe://chat/{conversationId}` — navigates to the thread.
4. Android: background app — foreground service notification visible; libp2p overlay still active.
5. iOS: background → foreground — connections recover without manual action.
