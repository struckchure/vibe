## Summary

Primary auto-signaling uses public WebSocket BitTorrent trackers. Both peers opening a mutual chat announce to the same `infoHash` (derived from `conversationId`), get matched by the tracker, and exchange encrypted signaling over a tracker-mediated WebRTC tunnel. Vibe's main `RTCPeerConnection` then completes the session. libp2p relay+rendezvous ([0008](0008.md)) remains fallback.

## Changes

- [`tracker-config.ts`](../src/lib/tracker-config.ts) — community `wss://` tracker catalog
- [`tracker-room.ts`](../src/lib/tracker-room.ts) — `infoHash` + stable tracker `peerId` from Vibe keys

## Flow

1. Add contact via `vibe://peer/…`
2. Open chat on both devices
3. Each announces to `infoHash = SHA256(conversationId)[0:20]`
4. Tracker introduces peers → WebRTC signaling tunnel opens
5. Encrypted SDP/ICE over tunnel → main Vibe PC → `vibe/text` + Noise

## Manual test

1. Two tabs or devices on different networks
2. Add contact, open chat both sides — auto-connect without `vibe://connect`
3. Messages send when tracker path works (no libp2p peer required)
4. Block trackers → libp2p fallback or Advanced manual connect

## Known limits

- Tracker operators see announce activity on `infoHash` (conversation fingerprint)
- `conversationId` is only known to mutual contacts (SHA-256 of both keys)
- Public tracker availability varies; catalog in `tracker-config.ts`
- Strict profile catalog-only enforcement is future work

## Security

Signaling payloads over the tracker tunnel use the same `encryptSignaling` / `decryptSignaling` path as gossipsub. The tracker tunnel is transport only, not the chat data plane.
